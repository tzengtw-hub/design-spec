# SDD-NNN：功能名稱

- 狀態：草稿 / 已確認 / 已完成
- 建立日期：YYYY-MM-DD
- 相關決策：（ADR 連結，沒有就寫「無」）

## 1. 為什麼要做
一兩句話說明這個功能解決誰的什麼問題。

## 2. 使用者會怎麼用
用「我想要……，所以我會……」描述 1–3 個情境。

## 3. 畫面需求
- 會出現哪些區塊、按鈕、文字
- 手機上看起來如何（手機優先）

## 4. 資料
- 會用到哪些資料、格式長怎樣（舉一個例子）；沒有真資料就寫假資料

## 5. 不做的事
明確寫出這次「不包含」的範圍，避免越做越大。

## 6. 驗收條件
- [ ] 條件一（要能實際操作驗證，例如「按下新增後清單多一筆」）
- [ ] 條件二
- [ ] 條件三
