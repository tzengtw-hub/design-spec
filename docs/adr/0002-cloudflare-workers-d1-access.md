# ADR-0002：後端用 Cloudflare Workers，資料庫用 D1，登入用 Cloudflare Access

- 狀態：已採用
- 日期：2026-10-27
- 相關規格：[SDD-001](../sdd/001-yacht-order.md)；延續 [ADR-0001](0001-full-system-with-login-and-database.md)

## 背景
ADR-0001 決定做正式系統（有登入、有資料庫）。
現在要選後端、資料庫、登入用什麼工具。這個選擇之後很難換。

## 考慮過的選項
1. 選項 A：Cloudflare 全家（Workers 跑後端、D1 當資料庫、Access 管登入）
   - 優點：範本已內建 Wrangler，上線方式不變；小型使用免費；全部在同一個帳號。
   - 缺點：角色（客戶／船廠人員／管理者）和「客戶只看自己的專案」要自己寫程式檢查。
2. 選項 B：Supabase（資料庫＋登入一起）
   - 優點：登入現成；權限可直接設在資料表上。
   - 缺點：要另外開帳號，多一個服務要管。
3. 選項 C：Firebase（Google）
   - 優點：文件多、上手快。
   - 缺點：資料庫不是表格式，版本紀錄、修改紀錄、條件對照比較繞。

## 決定
我們選擇「選項 A：Cloudflare 全家」，使用者在 2026-10-27 選定。

## 影響
- 變簡單：沿用範本的 `wrangler.jsonc` 和上線流程；資料是表格，適合做版本與修改紀錄。
- 變困難、要注意：
  - 權限檢查全部在 Worker 程式裡做，每個讀寫資料的地方都要檢查角色和專案擁有者。
  - 要建 D1 資料庫與資料表結構；改資料表結構的變更，合併前要先問使用者。
  - 要在 Cloudflare 帳號設定 Access 和 D1，金鑰只放環境設定，不貼進對話、不提交。
  - 測試環境只放假資料。
- 改回來：要把 Worker 的資料存取和登入檢查換掉，並搬移 D1 資料。
