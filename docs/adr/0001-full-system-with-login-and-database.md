# ADR-0001：做正式系統（有登入、有資料庫），不做單頁示範

- 狀態：已採用
- 日期：2026-10-27
- 相關規格：[SDD-001](../sdd/001-yacht-order.md)

## 背景
SDD-001 要分客戶和船廠人員兩種角色，客戶不能看到別人的專案。
規格書要存版本，法規摘要要記錄修改人和時間。
這些都要有登入和共用的資料庫才做得到。
但這個範本原本限制：只有一個 `index.html`、不用後端、不用登入、不用資料庫、只放假資料。
所以要先決定照範本限制做，還是做成正式系統。

## 考慮過的選項
1. 選項 A：課堂練習版（單頁示範）
   - 優點：照範本限制就能做，做得快，可以馬上預覽。
   - 缺點：沒有真的登入和權限，資料只存在自己的瀏覽器，別人看不到，規格 4.4 做不到。
2. 選項 B：正式系統版（有登入、有資料庫）
   - 優點：能照 SDD-001 原本的要求做到權限、版本紀錄、修改紀錄、多人共用。
   - 缺點：超出這個範本的範圍；要另外選後端和資料庫，要改專案規則；登入和權限要特別小心。
3. 選項 C：拆小做（先只做一個功能）
   - 優點：範圍小，先看到成果。
   - 缺點：只是延後決定，登入和資料庫的問題之後還是要面對。

## 決定
我們選擇「選項 B」，使用者在 2026-10-27 選定。

## 影響
- 變簡單：SDD-001 的權限、版本、修改紀錄都能照原規格做。
- 變困難：
  - 要另外決定後端、資料庫、登入用什麼技術（下一份 ADR）。
  - CLAUDE.md「網站的限制」那一節（一個 `index.html`、不用後端、不用登入、不用資料庫）要改寫。
  - `.claude/hooks/guard.py` 只讓 builder 改 `index.html`，要改設定才能做多檔案的系統。
  - 動到登入和權限的變更，合併前要先問使用者。
- 改回來：如果改回選項 A，要還原 CLAUDE.md 的限制，並把 SDD-001 的登入、權限、資料庫部分標成「不做」。
